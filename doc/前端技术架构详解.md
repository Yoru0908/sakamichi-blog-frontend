# 前端技术架构与逻辑详解

本文档详细介绍了坂道博客翻译系统前端 (`sakamichi-blog-frontend`) 的架构设计和核心逻辑。这是一个基于原声 Javascript 实现的单页应用 (SPA)。

## 1. 架构概览

前端采用无框架 (Vanilla JS) 的 SPA 架构，主要由以下核心模块组成：

- **`App` (app.js)**: 应用程序的入口点，负责全局初始化、API 连接检查和全局状态管理。
- **`Router` (router.js)**: 核心路由管理器，处理哈希路由 (Hash-based Routing)，管理视图切换。
- **`StructuredRenderer` (structured-renderer.js)**: 负责将后端的结构化双语数据渲染为 HTML。
- **UI 组件**: 包括分页、搜索、移动端菜单等独立模块。

## 2. 核心模块详解

### 2.1 Router (路由管理器)
**位置**: `js/router.js`

Router 是整个应用的控制中枢。它监听 `hashchange` 和 `popstate` 事件来响应 URL 变化。

#### 核心状态 (`Router.currentView`)
- `group`: 团体列表页 (例如 `#nogizaka`, `#all`).
- `member`: 成员个人主页 (例如 `#nogizaka/member/name`).
- `blog`: 博客详情页 (例如 `#blog/12345`).

#### 关键逻辑
1.  **路由解析 (`handleRoute`)**:
    - 解析 URL Hash（例如 `#nogizaka`）。
    - 提取参数（团体名、成员名、博客ID）。
    - 根据解析结果调用相应的显示方法。

2.  **视图切换**:
    - `showGroupPage(group)`: 显示博客列表。
    - `showMemberPage(member, group)`: 显示成员个人主页。
    - `showBlogDetail(blogId)`: 渲染博客详情。
    
    *注意*: 每次视图切换时，Router 会智能判断是否需要重新加载数据。例如，从详情页返回列表页时，它会恢复之前的滚动位置和页码，而不是刷新整个列表。

### 2.2 App (应用入口)
**位置**: `js/app.js`

#### 职责
1.  **API 发现**:
    - `determineInitialApiBaseUrl()`: 智能判断当前环境（本地开发 vs 生产环境）。
    - `ensureApiBaseUrl()`: 对候选 API 进行健康检查，自动选择可用的后端节点（应对跨国网络延迟或故障）。

2.  **数据加载 (`loadBlogs`)**:
    - 处理分页逻辑 (`offset`, `limit`)。
    - 处理筛选参数 (`group`, `member`, `search`).
    - **缓存策略**: 实现了一个简单的内存缓存 (`blogCacheMap`)，缓存已加载的列表页数据 (TTL 5分钟)，显著提升返回操作的流畅度。

3.  **无限滚动 vs 分页**:
    - 在 `#all` (全部) 页面，启用无限滚动机制。
    - 在特定团体页面（如 `#nogizaka`），使用传统翻页器。

### 2.3 StructuredRenderer (结构化渲染器)
**位置**: `js/structured-renderer.js`

#### 背景
后端 API 返回的博客内容不是纯 HTML，而是一种自定义的**双语结构化格式**，目的是精确控制原文和译文的对照排版，以及图片的插入位置。

#### 格式规范
- `[NEWLINE:N]`: 插入 N 个换行符。
- `[IMAGE:N]`: 插入第 N 张图片。
- 其他文本被视为正文段落。

#### 渲染流程 (`renderStructuredContent`)
1.  **解析**: 逐行读取内容。
2.  **图片插入**: 遇到 `[IMAGE:N]` 标记时，从 API 返回的 `images` 数组中取出对应的 URL (R2 链接)，生成 `<img>` 标签。
    - **性能优化**: 对首屏的前8张图片使用 `loading="eager"`，其他使用 `loading="lazy"`。
3.  **文本处理**: 处理普通文本行，支持 Markdown 语法（加粗、链接）。
4.  **生成 HTML**: 最终拼接为完整的 HTML 字符串供前端展示。

## 3. 页面逻辑流程

### 3.1 首页加载流程
1.  用户访问 `index.html`.
2.  `app.js` 初始化，连接后端 API。
3.  `Router.init()` 启动，解析当前 Hash (默认为 `#all`).
4.  调用 `showGroupPage('all')`.
5.  `loadBlogs()` 发起 API 请求 (`/api/blogs?limit=16`).
6.  数据返回 -> `StructuredRenderer` 渲染卡片 -> 插入 DOM.

### 3.2 博客详情页流程
1.  用户点击博客卡片 -> URL 变为 `#blog/{id}`.
2.  `Router` 捕获变化 -> 调用 `showBlogDetail({id})`.
3.  **请求优化**: 如果该博客数据已存在于列表缓存中，直接复用显示，避免网络请求。否则请求 `/api/blogs/{id}`.
4.  渲染详情视图：
    - 左侧/上方显示标题、日期、成员信息。
    - 中间区域调用 `renderStructuredContent` 显示正文。
    - 底部显示"原文链接"和"返回"按钮。

### 3.3 搜索与筛选
- **搜索**: 支持按成员名或关键词搜索。搜索结果会覆盖当前列表，并临时禁用无限滚动。
- **日期筛选**: 在搜索结果中，用户可以进一步指定 `startDate` 和 `endDate`，`app.js` 会通过 API 参数 (`from`, `to`) 过滤结果。

## 4. 工具库 (Utils)
**位置**: `js/utils.js`

提供了通用的辅助函数，最重要的是**日期格式化** (`formatDate`)。
- 输入: `2025-10-19T12:00:00Z`
- 输出: `2025.10.19 21:00` (转换为用户本地时间或指定时区)。
- 作用: 确保所有页面（列表、详情、搜索结果）的时间显示格式统一。
